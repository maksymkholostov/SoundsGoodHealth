Developer Guide

Go to Quick Start & Downloads Page

This guide covers two main parts:

  1. Using the SoundsGood Platform: How to register, manage your sound data (classes, dictionaries, recordings), and train custom sound recognition models.
  2. C# Integration: How to integrate the SoundClassifiers API into your C# application using the provided client library to make predictions with your trained models.

Part 1: Using the SoundsGood Platform (soundsgood.health)

This section walks you through the process of creating and training your custom sound classification models on the platform.

1. Registration and Login

  • Register: Go to /register to create a new account. You'll need to provide a username, email, and password.
  • Login: Once registered, log in via /login.

2. Understanding Core Concepts

  • Sound Class: A specific sound you want to recognize (e.g., "Ah", "Ee", "Oh", "Siren", "Dog Bark"). Each class needs a unique name. You define these first.
  • Dictionary: A collection of Sound Classes that a specific model will be trained to distinguish between. For example, a dictionary named "Vowels" might contain the classes "Ah", "Ee", "Ih", "Oh", "Oo". A model trained on this dictionary will only predict one of these vowel sounds.
  • Recording: An audio sample (.wav file) of a specific Sound Class. Recordings are used to train the model.
    • Raw/Pending: Recordings initially uploaded or recorded are often in a pending state.
    • Gold: Recordings that have been reviewed and confirmed to be good examples of their assigned Sound Class. Only Gold recordings are used for training.
  • Model: The machine learning algorithm trained on the "Gold" recordings within a specific Dictionary. It learns to differentiate between the Sound Classes in that dictionary.

3. Workflow: Training Your First Model

Here's the typical process from start to finish:

Step 3.1: Define Your Sound Classes

  • Navigate to the "Classes" section (usually via a sidebar link or /classes).
  • Click "Create New Class" (or similar).
  • Enter a unique name for the sound (e.g., "Mah").
  • Repeat for all the distinct sounds you want your model to recognize.

Step 3.2: Create a Dictionary

  • Navigate to the "Dictionaries" section (/dictionaries).
  • Click "Create New Dictionary".
  • Give the dictionary a descriptive name (e.g., "Basic Syllables", "Environmental Sounds").
  • Select the Sound Classes (created in Step 3.1) that you want this dictionary to include. A model trained on this dictionary will only be able to predict the classes within it.
  • Save the dictionary.

Step 3.3: Add Recordings for Each Class

  • Navigate to the "Record" or "Upload" section (/record, /upload).
  • For each Sound Class in your Dictionary:
    • Select the target Sound Class.
    • Either Record new samples directly through your browser (if supported) or Upload existing .wav files from your computer.
    • Aim for variety: Record sounds with slightly different intonations, volumes, etc.
    • Quantity: More high-quality recordings (10-20+ per class) generally lead to better models.

Step 3.4: Verify Recordings (Create "Gold" Data)

  • Navigate to the "Verify" or "Manage Recordings" section (/verify).
  • Select a Dictionary or Sound Class to review its recordings.
  • Listen to each "Pending" recording.
  • If it's a clear, accurate example, mark it as "Gold" (or "Approve").
  • If it's poor quality or incorrect, Discard or Reject it.
  • This step is crucial. Only Gold recordings are used for training.

Step 3.5: Train the Model

  • Navigate to the "Training" section (/training).
  • Select the Dictionary you want to train a model for.
  • Choose the Model Type (e.g., CNN, RF).
  • Give your model a descriptive Name.
  • Click "Start Training".

Step 3.6: Monitor Training and View Results

  • The platform should indicate training status.
  • Once "Trained", you can usually view results (Accuracy, etc.).
  • The **Model ID** is assigned upon successful training. **This is the ID you need for API integration.**

4. Using Your Trained Model (via API)

  • Navigate to the "Developer Resources" page (/developer) or the "Quick Start" page (/developer/downloads).
  • Find your trained model in the list and copy its **Model ID**.
  • Follow the steps in **Part 2: C# Integration** below.

Part 2: C# Integration

This section explains how to integrate the SoundClassifiers API into your C# application using the provided client library.

Prerequisites

  1. Trained Model: You need at least one model trained on the SoundsGood platform.
  2. .NET Environment: A working C# development environment.

Integration Steps

1. Get the C# Client Library:

  • Download the client package: SoundClassifiers_CSharp_Client_Package.zip
  • Extract the ZIP file.
  • Add the SoundClassifiersClient.cs file to your C# project.

2. Add Required NuGet Packages:

Ensure your project references these NuGet packages:

  • Newtonsoft.Json
  • NAudio (Optional, only if capturing microphone audio)

3. Find Your Model ID:

  • Go to the Quick Start page.
  • In the "Your Trained Models" section, find the model you want to use.
  • Copy the **Model ID**.

4. Initialize the SoundClassifiers Client:

Replace Azure initialization with this:

// Add this at the top of your file
using SoundClassifiersClient;

// --- SoundClassifiers Integration ---
// Remove or comment out Azure SpeechConfig and SpeechRecognizer initialization

// Initialize the SoundClassifiers client:
var scClient = new SoundClassifiersClient(
    baseUrl: "https://www.soundsgood.health", // Base URL of the SoundsGood API
    modelId: "PASTE_YOUR_MODEL_ID_HERE", // Paste the Model ID you copied
    apiKey: null // *** API Key is not currently required, pass null ***
);
// --- End SoundClassifiers Integration ---

5. Perform Recognition:

Replace Azure event handlers and `StartContinuousRecognitionAsync` with direct calls:

6. Adapting Existing Code:

  • Remove Azure SDK: Delete using Microsoft.CognitiveServices.Speech;. Uninstall the NuGet package.
  • Replace Initialization: Swap `SpeechConfig`/`SpeechRecognizer` for `SoundClassifiersClient` creation.
  • Replace Event Logic: Remove `speechRecognizer.Recognizing += ...`, etc.
  • Replace Recognition Trigger: Replace `Start...Async`/`RecognizeOnceAsync` with `await scClient.Recognize...Async(...)`.
  • Use New Result: Adapt logic to use `result.Phoneme`, `result.Confidence`.

Understanding the Recognition Result

The `RecognitionResult` object contains:

  • `Success` (bool): API call status.
  • `Phoneme` (string): Top prediction (null/empty if no match or !Success).
  • `Confidence` (double): Score (0.0-1.0).
  • `Alternatives` (List<RecognitionAlternative>): Other possibilities.
  • `Error` (string):** Error details if !Success.

Important: Always check `result.Success` before using other properties.

Handling Audio Data

  • Expected Format: WAV format (16kHz, 16-bit PCM, mono recommended).
  • `RecognizeFromFileAsync`:** Needs a path to a valid WAV file.
  • `RecognizeFromDataAsync`:** Needs a `byte[]` containing data *already in WAV format*.
  • Recording:** Use `NAudio` (like in `SoundClassifiersExample.cs`) to capture and convert to WAV bytes before sending.

Error Handling Strategy

  1. Check `result.Success`.
  2. If `false`, check `result.Error`.
  3. If `true` but `Phoneme` is empty, handle "No Match".
  4. Wrap `await scClient.Recognize...` in `try...catch` for network/file errors.
// Example incorporating error handling
try
{
    RecognitionResult result = await scClient.RecognizeFromFileAsync(filePath);

    if (result != null && result.Success)
    {
        if (!string.IsNullOrEmpty(result.Phoneme))
        {
            // Successfully recognized
            Console.WriteLine($"OK: {result.Phoneme} ({result.Confidence:P})");
            // >> Your logic <<
        }
        else { /* Handle No Match */ }
    }
    else { /* Handle API Error using result?.Error */ }
}
catch (System.Net.Http.HttpRequestException httpEx) { /* Handle network error */ }
catch (Exception ex) { /* Handle general exception */ }

Troubleshooting Common Issues

  • "Model not found": Check Model ID, ensure model is trained.
  • Connection Errors: Check internet, base URL (`https://www.soundsgood.health`), Railway status.
  • "Invalid audio format": Ensure WAV format (16kHz, 16-bit PCM, mono). Check WAV header if using `RecognizeFromDataAsync`.
  • Low Confidence/Incorrect Recognitions:** Retrain model with more/better data.
  • No Recognition / "No Match": Check mic, audio levels, background noise.
